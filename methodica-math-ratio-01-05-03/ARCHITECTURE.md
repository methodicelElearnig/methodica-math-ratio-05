## MultipleChoiceQuestion (MCQ) — רכיב חדש, החוזה המלא
אין מופע קודם בפרויקט הזה — זו הפעם הראשונה שנבנה. בנוי כאח-קרוב-מבנה
של SCQ (720-templates skill → `MultipleChoiceQuestion.md`), עם הבדל
התנהגותי יחיד: בחירה היא Set, לא ID יחיד.

**Markup contract:**
```html
<div class="scq-answers" role="group" aria-label="...">
  <div class="scq-opt" role="checkbox" aria-checked="false" tabindex="0"
       data-id="a" onclick="mcqToggle('KEY','a')">
    <span class="scq-opt-text">...</span>
    <span class="scq-radio"></span>
  </div>
  <!-- אחד לכל אפשרות -->
</div>
```
`role="checkbox"` על כל אפשרות (לא `role="radio"`), `role="group"` על
המכיל (לא `role="radiogroup"`) — טעות-נגישות ידועה שהמפרט הזהיר ממנה
במפורש. אותה `.scq-opt`/`.scq-radio` חזותית **בדיוק** כמו ב-SCQ — אין
CSS חדש כלל, רק ARIA-role שונה ב-HTML.

**JS contract** (`script.js`):
- `mcqState[key] = { selected: Set, attempts, outcome }`.
- `mcqToggle(key, id)` — מוסיף/מסיר **רק** את ה-id שנלחץ; לעולם לא
  מנקה בחירות-אחיות (ההבדל המהותי היחיד מ-`scqSelect`).
- שער-הפעלה לכפתור-בדיקה: `selected.size >= 1` — לא "בדיוק N".
- `mcqCheck(key)` — נכונות = שוויון-Set מלא (`setsEqual`, פונקציה
  גלובלית חדשה) מול `cfg.correctIds` — לא חלקי, לא "כמעט-נכון".
  ניסיון ראשון שגוי: מסמן רק את הבחירות-השגויות של הלומד/ת כ-`.wrong`,
  לא חושף כלום. ניסיון סופי שגוי: מסמן **כל** ה-`correctIds` כ-`.correct`
  (גם אם לא נבחרו), וכל בחירה-שגויה כ-`.wrong` — אותה מוסכמת-חשיפה
  בדיוק כמו SCQ/VIQ, מוכללת ל-Set.
- `mcqFinish(key)`/`MCQ_CFG` — מבנה זהה ל-`scqFinish`/`SCQ_CFG`
  (`containerSel`, `correctIds` במקום `correctId`, `checkBtnId`,
  `feedboxId`, `correctMsg`/`wrongOnce`/`wrongFinal`, `onDone`).

**מופע יחיד בפועל כרגע:** `s3p3` (מסך 4, חלק ג', `#s3-part-3`,
`correctIds:['a','c']`). מיועד-לקידום ל-reference file של הסקיל ברגע
